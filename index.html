Проекты

Сайт ГКБ № 24, gkb-24.ru

Публичный сайт московской городской клинической больницы № 24. Разработал с нуля и сопровождаю: онлайн-запись пациентов, страницы врачей и отделений, SSR на Next.js App Router, серверная часть на Express. Один код обслуживает два сайта, больницы и медицинского центра, с разной картой сайта, разметкой и маршрутизацией по поддомену.

Админ-панель на 12 разделов с доступом по ролям: с ней работают 20 сотрудников из разных отделов больницы, в том числе колл-центра и маркетинга. Веду техническое SEO и GEO-оптимизацию под Яндекс и Google, через Cloudflare настроил DNS, проксирование трафика и SSL.

Около 40 000 визитов в месяц на двух сайтах. Больше 3 500 обращений пациентов за полгода, сейчас около 30 в день, каждое четвёртое приходит через ботов Telegram и MAX.

Система координации госпитализаций

Ежедневный автоматический сбор данных о направлениях на госпитализацию с государственной медицинской платформы: headless-браузер на Playwright, вход через государственный SSO, запуск по расписанию. Как работаю

Инженерные практики из работы над сайтом больницы.

Надёжные релизы

Сборка идёт в отдельный каталог, переключение только после успешной сборки. При любом сбое выкатка сама откатывает код, зависимости и сборку. Сам скрипт покрыт тестом в изолированном репозитории.

Тесты проверяют правила проекта

Около 1000 автотестов на Jest и supertest, интеграционные тесты на изолированных PostgreSQL и Redis, CI на GitHub Actions. Часть тестов проверяет сами правила: каждая запись в админке попадает в журнал аудита, каждый публичный POST проверяет тело запроса до ограничителя частоты.

Безопасность

Аудит backend: валидация входных данных, ограничение частоты запросов, проверка Origin против CSRF, JWT-сессии с возможностью отзыва, блокировка подбора логина, защита выгрузок Excel и CSV от инъекции формул. Состояние сервера проверяется по расписанию.

Персональные данные

IP-адреса хранятся только в виде хеша с солью, идентификаторы в журналах обезличиваются автоматически, публичные API не отдают адреса получателей писем.

SEO как инженерная задача

Скрипт собирает сайт, обходит около 290 публичных адресов и проверяет canonical, JSON-LD, sitemap и редиректы. Накопленный SEO-долг доведён до нуля, а проверка перед выкатом не даёт ему вернуться.

Мониторинг

Watchdog на базе systemd timer следит за приложением и присылает уведомления о сбоях. Для инцидентов есть инструкция по реагированию.

Работа с ИИ-агентами

В разработке использую Claude Code и Codex. Веду задачи по этапам: план, реализация агентом, ревью, тесты, обновление правил проекта. Результат проверяю тестами и ревью, коммиты и выкладку контролирую сам.

Порядок в процессах

Перевёл постановку задач в двух отделах больницы из личных сообщений в общую доску задач: видно, кто, что и в какие сроки делает. Веду документацию проекта: правила, инструкцию по авариям, журнал решений.
